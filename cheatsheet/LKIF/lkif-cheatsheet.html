01总览 · 法律概念的一套积木 PART 1 · OVERVIEW

LKIF Core(Legal Knowledge Interchange Format Core)是欧洲 ESTRELLA 项目产出的法律领域本体库:15 个模块,从「部分与整体」一路铺到「规范、权利与法律渊源」。三族结构:

主线:法律规范是「说出来的」——先有命题与陈述(expression),再被资格化为规范(norm),配规则(rules)与时效(modification)。
本卡结构 = 本图:概览 → 三族模块 → 表达与规范 → 规则与实操。
02定位 · 一个项目,一份遗产 PART 1 · POSITION

LKIF Core 是欧盟 FP6 项目 ESTRELLA 的交付物(D1.1):v1.0(2007-02)→ v1.1(2008-07),此后停止演进。2026 年 2 月仓库转 CC BY 4.0 许可并补了 Turtle 版(RDF/XML 已弃用)。

04表达层 · 规范之前先有话 PART 2 · EXPRESSION MODULE

LKIF 的关键设计:规范不是凭空出现的,它是「被资格化的表达」。expression 模块先搭好语言的层:

类一句话
Proposition命题——可真可假的内容本身
Propositional_Attitude命题态度:相信、意图……(谁对它持什么态度)
Evaluative_Proposition评价性命题:带价值判断的断言
Qualification / Qualified资格化:给事物贴上定性标签——norm 模块直接踩在这个机制上
Expression · Communicated_Attitude表达出来的内容与「说出来」这一传播行为;Medium 是媒介
05规范层 · 资格化 + 权利类型学 PART 2 · NORM MODULE

norm 模块把规范定义为「资格化的表达」,再铺开三组概念——义务禁止、霍菲尔德式权利、法律渊源:

规范与遵守 义务侧

  • Norm · Normatively_Qualified——被规范作用的对象
  • Obligation / Permission / Prohibition——义务、许可、禁止
  • Allowed / Disallowed(及 Strictly 变体、Allowed_And_Disallowed 冲突态)
  • Belief_In_Violation · Observation_of_Violation——违规的「 believed / observed」两条记录线

权利类型学 霍菲尔德式

  • Obligative_Right(请求权)· Liberty_Right(自由权)
  • Permissive_Right · Exclusionary_Right · Liability_Right · Potestative_Right
  • 权力:Hohfeldian_Power · Enabling_Power · Declarative_Power · Immunity
法律渊源 · 从成文法到软法
成文Statute · Code · Regulation · Decree · Directive · Resolution · Proclamation 不成文Custom · Customary_Law · Legal_Doctrine 判例Precedent · Mandatory_Precedent · Persuasive_Precedent 国际Treaty · International_Agreement(含 Non-binding)· Soft_Law Contract合同在 norm 模块里也是一种法律渊源
关系属性 allows / allowed_by、commands / commanded_by、disallows / disallowed_by 三对互逆;规范之间有 normatively_comparable / equivalent_or_better / strictly_better 一族排序关系——「此规范优于彼规范」也是可推理的。
规范排序 · normatively_* 一族
关系含义(A ? B)
normatively_comparable两者在同一评价尺度上,可以比较
normatively_equivalent_or_better / _or_worse不劣于 / 不优于
normatively_strictly_better / _strictly_worse严格优于 / 严格劣于
normatively_not_equivalent不可互换
06行动与角色 · 权力是关键词 PART 2 · ACTION & ROLE

action 模块把行动定义为「行动者执行的过程」,并给出法律里最值钱的那个词:Power。role 模块用 plays 把实体和它扮演的角色分开——「张三」与「法官」是两回事。

action 行动词表

  • Action · Agent——行动与行动者
  • Act_of_Law · Decision · Assignment · Delegation · Mandate · Transaction

role 角色词表

  • Role · Epistemic_Role · Function · Social_Role · Organisation_Role
  • 实体「扮演」角色:不把职业写进人的类,而是用 plays 关联

07规则与时效 · 让法律可推理 PART 3 · RULES & MODIFICATION

两个框架模块负责「动」起来:rules(lkif-rules)定义规则语法与论证角色,为 LKIF Rules RDF 语法服务,并给 AIF、Carneades 等论证框架留了扩展位;modification 给法律条文加上时间轴——生效 / 失效区间(efficacy / in-force)与修改类型学。

rules 推理入口

  • 规则 = 前件 → 后件,挂论证角色
  • 与第 05 节的 norm 概念对接:「违反规范」是可推导的结论
  • 复杂论证框架(AIF / Carneades)可在此基础上扩展

modification 时间轴

  • 法条的 efficacy 区间:「从何时起有效」
  • in-force 区间:「此刻是否现行」
  • 修改类型学:修订 / 废止 / 新增各成一类
配套 法律文档的结构化(条款编号、层级)不在 LKIF 里——看 MetaLex/CEN;两个项目在历史上互相兼容。
08示例 · 规范这样编码 PART 3 · A WORKED NORM

「禁止路边停车」一条法律知识,用 norm 与 expression 两模块的已核实词汇编码:

ex:禁停条款 a lkif-norm:Norm ; lkif-norm:disallows ex:路边停车 . # 规范禁止该行为资格 ex:路边停车 a lkif-expression:Qualification . # 行为被资格化 ex:罚单记录 a lkif-norm:Belief_In_Violation . # 违规的信念记录线
读法 条款(Norm)用 disallows 指向被资格化的行为;真被开了罚单,再记一条 Belief_In_Violation——「规范存在」与「违规被认定」是两个层面。
09实操坑清单 PART 4 · PITFALLS
  1. 官网域名已易主:estrellaproject.org 现在是无关站点——本体文件一律从 GitHub 镜像(RinkeHoekstra/lkif-core)取,优先 .ttl。
  2. 2008 年后停更:v1.1 是终点;新项目做法律规则先评估 LegalRuleML,LKIF 更适合当「法律概念参考层」。
  3. norm 类名以 norm.owl 原文为准:Obligation、Hohfeldian_Power、Liability_Right 这些拼写带下划线大写,别按惯例改成小驼峰。
  4. top 层承诺度高:继承自 LRI-Core,引入整个 top 会带入大量你未必想要的公理——只要 norm / action 时可考虑裁剪导入。
  5. 15 模块可拆用:lkif-core.owl 是集成入口,不需要法律层时 mereology / time 可单独复用。
  6. 与政策词表分工:ODRL(PL.09)管「许可与义务的政策表达」,LKIF 管「法律概念与法律推理」——合同里的义务描述可两者配合。
  7. 合同建模的分工:合同作为法律渊源在 lkif norm 模块(Contract 类);经费项目的合同实体在 FRAPO(PL.17);金融衍生合同另看 FIBO。
  8. Spacetime 模块已成历史:v1.0.2 起移除,别按老文档 import。
  9. 规范排序是一族六条:normatively_comparable / equivalent_or_better / worse / strictly_better / strictly_worse / not_equivalent——表达「法条优劣」按语义选,别全用 comparable。
