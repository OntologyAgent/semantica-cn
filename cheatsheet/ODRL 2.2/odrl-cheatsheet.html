01总览 · 把「许可条款」写成数据 PART 1 · OVERVIEW

ODRL 把许可条款写成数据:政策里放规则,规则作用在资产的行动上,约束与冲突策略管边界;给 Web 的形态就是 JSON-LD。

主线:一条规则 = 当事人对资产的一项行动,外加约束与违约后果。
本卡结构 = 本图:概览 → 规则细节 → 完整形态 → 生态与实操。
02定位 · 把「许可条款」写成数据 PART 1 · POSITION

数据能看、能用、能转发吗?给谁看?要署名吗?付费吗?ODRL(Open Digital Rights Language)用一份机器可读的政策(Policy)回答这些——权利、义务、约束全部结构化,授权链路可以自动执行。

03三种政策 · Set / Offer / Agreement PART 1 · THREE POLICY TYPES

规则侧 Rules

  • Permission:允许做什么——必须有 target,可挂 duty(先决义务)
  • Prohibition:禁止做什么——违规可挂 remedy(补救)
  • Duty:必须履行的动作——违约可挂 consequence(后果)

政策侧 Policy subclasses

  • Set:默认;只是规则的集合,无法律角色
  • Offer:要约——assigner 已定,等对方接受
  • Agreement:合约——assigner 与 assignee 都已落定
名字的陷阱 obligation 是 Policy 上的属性(把 Duty 挂为义务),不是类;类是 Duty。而 Permission 上的 duty 属性语义是「行使该许可的先决条件」——先付费,才能播放。

04Action 词汇 · 规范只定义两个,其余靠词表 PART 2 · ACTION VOCAB

信息模型顶层只定义 odrl:use(使用,兜底动作)与 odrl:transfer(转让所有权);Common Vocabulary 给出通用动作集(规范正文示例中出现):

play播放
display展示
print打印
distribute分发
reproduce复制
index索引
stream流式
attribute署名
compensate付酬
anonymize匿名化

acceptTracking接受追踪

扩展动作 自定义 Action 用 includedIn(收窄到已知动作,机器可下推)或 implies(蕴含声明)。行业词表另有大动作集——用谁的词表,Policy 里声明谁的 profile。
05Constraint · 给动作上条件的标准件 PART 2 · CONSTRAINTS
# 结构三件套:leftOperand + operator + rightOperand(或引用) [ odrl:leftOperand odrl:dateTime ; odrl:operator odrl:lteq ; odrl:rightOperand "2026-12-31"^^xsd:date ] . # 付费额度带单位 [ odrl:leftOperand odrl:payAmount ; odrl:operator odrl:lteq ; odrl:rightOperand "5.0" ; odrl:unit "EUR" ] .
件说明
leftOperand约束什么:dateTime、count、payAmount、event、media、resolution…(外部词表可加,如 foaf:age)
operator规范示例出现:eq / lt / lteq / gt;完整集以 Common Vocabulary 为准
rightOperand / …Reference字面量 / 指向外部资源的 IRI——二者恰选其一
unit / dataType / status单位、数据类型、状态(可选用)
06LogicalConstraint · 组合约束 PART 2 · LOGICAL CONSTRAINTS
# 四选其组合:只能「和水」或「和果汁」一起用,不可单独使用(示例场景) [ odrl:and ( … ) ] # 全部成立 [ odrl:or ( … ) ] # 任一成立 [ odrl:xone ( … ) ] # 恰好其一 [ odrl:andSequence ( … ) ] # 依序全部成立(顺序有意义,列表保序)
顺序有语义 andSequence 用 RDF 列表(@list)承载——校验器必须保序。要表达「先注册后下载」,用它而不是 and。
07冲突策略 · 两条规则打架听谁的 PART 2 · CONFLICT STRATEGY
odrl:conflict语义
odrl:perm许可优先——冲突时 Permission 赢
odrl:prohibit禁止优先——冲突时 Prohibition 赢
odrl:invalid默认值:有冲突,整份 Policy 作废
默认最严 不写 conflict 等于 invalid——任何冲突让整份政策无效。稳妥的政策都会显式声明策略;多值冲突同样按 invalid 处理。
08违约路径 · consequence 与 remedy PART 2 · BREACH PATHS

Duty 违约 consequence

  • Duty 未履行 → 追加新的 Duty(滞纳金、补救动作)
  • consequence 上不得再挂 consequence——链条只有一层
  • Permission 上的 duty 是先决,履行了才可行使

Prohibition 违禁 remedy

  • 触犯禁令 → 挂 remedy 指定的补救 Duty
  • remedy 不得指向带 consequence 的 Duty
  • 补救完成,违规才算了结
履行语义 Duty 的定义是「行使某 Action 的义务」——它自己带 action、constraint、assignee,本质是一条自足的小规则。设计政策时先画「履行/违约」两条分支,再翻成 ODRL。

10JSON-LD 形态 · 同一份政策给 Web PART 3 · JSON-LD FORM

ODRL 的 JSON-LD context 官方托管在 http://www.w3.org/ns/odrl.jsonld——同一政策,API 世界读 JSON,图谱世界读 RDF,零转换成本。

{ "@context": http://www.w3.org/ns/odrl.jsonld, "@type": Offer, uid: http://example.org/policy:42, permission: [{ assigner: http://example.org/org:42, target: http://example.com/asset:77, action: display, constraint: [{ leftOperand: dateTime, operator: lteq, rightOperand: { @value: "2026-12-31", @type: xsd:date } }] }] }
双形态纪律 同一政策的 Turtle 与 JSON-LD 两种写法必须指向同一 uid——两处各改各的,是 ODRL 落地最常见的事故源。
11Profile 机制 · 用别人的词表先报备 PART 3 · PROFILE MECHANISM
规则说明
odrl:profile政策用了核心之外的术语,必须声明 profile IRI——处理方遇到不认识的 profile 应当停止处理
扩展途径新 Policy/Rule 子类;relation/function/operand 的子属性;Action 用 includedIn/implies 挂树;新增 LeftOperand、Operator、ConflictTerm 实例
Core 剖面只用核心词汇时可不声明;核心标识 …/odrl/2/core
硬性项盘点 Policy 必须有 uid 与至少一条规则(permission/prohibition/obligation 三选一以上);Rule 必须有 action;Permission 必须有 target;右操作数二选一必填。缺一件,政策不合法。

13实操坑清单 PART 4 · PITFALLS
  1. obligation 是属性不是类——「义务」的类叫 Duty,挂接用 odrl:obligation。
  2. Permission 上的 duty 是先决义务,不是并列义务;并列的义务各起一条 Permission/Duty。
  3. consequence 只有一层:违约后果的后果没法表达,重排政策结构。
  4. remedy 不得指向带 consequence 的 Duty——规范原文禁令。
  5. 默认 conflict=invalid:政策里有一条冲突,整份作废——显式声明冲突策略。
  6. 规则子类彼此不相交:一条规则不能既是 Permission 又是 Prohibition。
  7. 用了 Common Vocabulary 之外的动作/操作数,声明 profile——否则合规处理器按规范应拒收。
  8. andSequence 保序靠 RDF 列表:序列化器不支持 @list 时会静默丢序。
  9. uid 是政策唯一标识(必备);资产与当事人 uid 是 SHOULD——多系统对接前补齐。
  10. ODRL 表达「政策」不执行「政策」:执行要在数据管线里另做(引擎比对动作与约束)。
  11. 与 CC 许可互转没有官方映射:Creative Commons 条款有自有表达,转换要人工核对语义。
