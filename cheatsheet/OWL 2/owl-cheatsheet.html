01总览 · RDF 之上的本体语言 PART 1 · OVERVIEW

OWL 2 在 RDF 上加本体表达:类构造子造类,属性特征加语义,公理说话,推理机按剖面算账。先开两大思维开关——开放世界、无唯一名。

03开放世界 + 无唯一名 · 两大思维开关 PART 1 · TWO MINDSET SWITCHES

开放世界假设 OWA

  • 没写的≠没有——查不到 only C 的反例,不算违反
  • 推不出「完整」:要闭合,显式写 oneOf / maxCardinality 0
  • 「为什么推理机没推出」的第一答案:知识不全,或需显式闭包

无唯一名假设 no UNA

  • 两个 IRI 默认可能是同一个体
  • 要确认不同,写 DifferentIndividuals
  • 要合并,写 SameIndividual;函数属性、键都会参与个体合并推理
典型翻车 「给了 maxCardinality 1 和两个不同的值,怎么不报错?」——因为推理机不知道那两个值不同!补 DifferentIndividuals(a b) 或改用函数属性+枚举,矛盾才浮出水面。
想要闭世界 · 四种显式闭合手段
手段闭合什么
ObjectOneOf(a b c)枚举:这个类的个体只有这几个
maxCardinality 0显式禁止某属性取值
DifferentIndividuals声明「这几个名字确指不同个体」
SHACL(PL.07) closed shapes数据级校验的闭合,不动本体语义

06全称量词的陷阱 · 空集也是「都」 PART 2 · UNIVERSAL QUANTIFIER TRAP
逻辑事实 「所有 p 都是 C」对没有任何 p 的个体同样成立——空集上的全称命题恒真。想让「必须至少有一个」,全称要与存在量词联用,或直接用基数 min 1。
Turtle 里限制的真实长相(标准 Restriction 节点)
:Pizza rdfs:subClassOf [ owl:onProperty :hasTopping ; owl:someValuesFrom :TomatoTopping ] , # 必须有番茄 [ owl:onProperty :hasBase ; owl:allValuesFrom :ThinBase ] , # 只许薄底 [ owl:onProperty :hasTopping ; owl:minQualifiedCardinality "3"^^xsd:nonNegativeInteger ; owl:onClass :Topping ] . # 配料至少三种
限定 vs 非限定 minCardinality 只数个数,minQualifiedCardinality 还要求值的类型——限定位是 OWL 2 新增,建模时优先用它,信息量翻倍。
07属性特征 · 七个标签一张表 PART 2 · PROPERTY CHARACTERISTICS
特征Functional Syntax语义备注
传递TransitiveObjectProperty(p)p(x,y) ∧ p(y,z) → p(x,z)祖先关系、部件包含
对称SymmetricObjectProperty(p)p(x,y) → p(y,x)婚姻、邻居
非对称AsymmetricObjectProperty(p)p(x,y) → ¬p(y,x)强于反自反;须简单属性
自反ReflexiveObjectProperty(p)全域个体 p(x,x)注意是「全域自反」
反自反IrreflexiveObjectProperty(p)¬p(x,x)父子、大于;须简单属性
函数FunctionalObjectProperty(p)p(x,y) ∧ p(x,z) → y=z生日;数据属性同理
反函数InverseFunctionalObjectProperty(p)p(y,x) ∧ p(z,x) → y=z社保号——值定主语,天然的「键」
简单属性(simple)限制 参与非对称、反自反、不相交、基数限制的属性必须是「简单属性」——不能处在属性链或传递闭包的圈里。这条全局限制正是可判定性的门票;违反即本体语法非法。

08属性链与键 · OWL 2 的两件新兵 PART 2 · PROPERTY CHAINS & KEYS
# 属性链:两条属性首尾相接,推出第三条(规则形状!可判定) SubObjectPropertyOf( ObjectPropertyChain( :hasMother :hasSister ) :hasAunt ) # 读法:有母亲 m,且 m 有姐妹 s,则 s 是姨母 # 键:同一键值(这里是身份证号)必属同一个人 HasKey( :Person :ssn ) # 语义:若两人 ssn 相同 → SameIndividual;注意键的推理只在「有名字的个体」间生效
链 vs SWRL 属性链是「如果…则…」最安全的一种:留在 DL 内、可判定、主流推理机全支持。需要变量比较、函数、否定判断的规则,才轮到 SWRL(PL.05)或规则引擎(剖面 RL)。
09逆向属性 · 双向都写还是写一边 PART 2 · INVERSE PROPERTIES
InverseObjectProperties( :hasPart :partOf ) # 声明后写一边即可,另一边由推理补全——两处都写是冗余,漏写一边才有信息
Top / Bottom owl:topObjectProperty(万物皆连)、owl:bottomObjectProperty(无人相连)、数据侧同款。bottom 与任何属性不相交,常用来「宣布不可能」。

OWL 2 与 RDFS 的 domain/range 分野 RDFS 的 domain/range 只会补类型(引 PL.02);OWL 2 DL 里它们是逻辑公理——数据违反可推出矛盾(如个体既属 C 又属 ¬C),推理机报「不一致」。同一个词,两种强度,加载模式说了算。
# 同一声明,两种后果 ObjectPropertyDomain( :hasAuthor :Book ) # OWL 2 DL:hasAuthor 的主语必是 Book :hasAuthor rdfs:domain :Book . # RDFS 模式:主语被推成 Book,永不报错 # 数据::robot :hasAuthor :alice 且 :alice owl:differentFrom 任何 Book 实例 # → OWL DL 模式:本体不一致;RDFS 模式::robot a :Book,岁月静好

13注解与 punning · 元数据的合法身份 PART 3 · ANNOTATIONS & PUNNING

注解 annotations

  • rdfs:label、rdfs:comment、owl:versionInfo…挂在本体、类、属性、个体上
  • Direct Semantics 不解释注解——它们不影响推理,错了也不报不一致
  • 要严格化元数据(如版本溯源),配 PROV-O(PL.11)

Punning 一名多角

  • OWL 2 DL 允许同一 IRI 在不同公理里当类又当个体(受限的多态)
  • 例::Dog 既是一个类,又是「狗类」这个分类学概念个体
  • 元建模的合法姿势,OWL 1 里要靠『0001』式歪招

14三剖面 · 用表达力换效率 PART 4 · THREE PROFILES
剖面为谁而生复杂度(一致性等)拿掉了什么
OWL 2 EL超大规模术语表(SNOMED CT 级生物本体)PTIME-complete全称量词、并/补、基数、枚举(多个体)、属性特征大半;保留存在量词、链、传递

17不一致急救流程 · 推理机报错之后 PART 4 · INCONSISTENCY FIRST AID
  1. 先定位本体还是数据:只加载 TBox 跑一致性——TBox 干净就查 ABox 断言。
  2. 二分公理:注释掉一半再跑,迭代逼近肇事公理(Protégé 的 explain 功能可自动做)。
  3. 常见肇事者:domain/range 滥用、缺 DifferentIndividuals 的基数冲突、把校验需求错写进 OWL。
  4. 修完跑剖面校验:确定本体仍在目标剖面(EL/QL/RL)内,再上线。

21实操坑清单 PART 5 · PITFALLS
  1. 全称量词对「没有 p 的个体」恒真——要「必须有」,用 min 1 或与 someValuesFrom 联用。
  2. 没写 DifferentIndividuals,两个 IRI 可能是同一个人——基数冲突不报错,多半是缺不同声明。
  3. domain/range 在 OWL 2 DL 里是硬公理,违反即不一致——RDFS 的「补类型」直觉在这里会害你。
  4. 非对称/反自反/不相交/基数参与者必须是简单属性——挂过链或传递的属性越界即语法非法。
  5. hasKey 只在有名字的个体间触发推理,别当数据库唯一约束用;真校验去 SHACL。
  6. OWA 下「闭世界式」需求要显式闭合:oneOf、max 0、differentFrom。
  7. 选剖面先选任务:大术语表 EL、库上查询 QL、规则引擎 RL;剖面互不包含,别幻想通吃。
  8. owl:imports 是公理并集,对方改版你遭殃——钉 version IRI。
  9. 注解不参与 Direct Semantics:标签写错不报错,发布前人工过。
  10. 复杂度是上限不是承诺:DL 推理在病态本体上指数爆炸,大 ABox 优先考虑 QL/RL 路线。
  11. punning 有度:同一 IRI 的多角色要服务同一叙事,否则读本体的人比推理机先崩溃。
  12. 空表达式与 owl:Thing 滥用:把 owl:Thing 写进限制位、或造出必然为空的类,推理机轻则告警重则 unsatisfiable。
  13. 构面 facet 只能收紧已知类型:pattern 配 string、minInclusive 配数值——张冠李戴即越出数据类型词表。
  14. DL 模式与 Full 模式混读:文档同时被两种语义解释,团队讨论先统一「今天在哪个语义里说话」。
  15. 发布前跑剖面校验器:表达力悄悄越档(多用了一个基数),下游 QL/RL 工具直接拒载。
