01总览 · 给「带单位的数值」立户口 PART 1 · OVERVIEW

QUDT(Quantities, Units, Dimensions and Types)是单位与量类的事实标准词表:测量写成结构化的 Quantity,数千个单位挂在 unit: 词表,量类用 7+1 维量纲向量判亲缘,换算只靠乘数与偏移两个数字。四层结构:

主线:同一个量允许多套单位——换算不靠聪明,只靠每个单位自带的 conversionMultiplier / conversionOffset,机械且无歧义。
本卡结构 = 本图:概览 → 数据模型 → 单位与量类 → 实操。
02定位 · 工程界的单位百科 PART 1 · POSITION

QUDT 由非营利组织 QUDT.org 维护,词表源头是 NIST 指南(SP 811)、BIPM SI 手册与国际计量词汇(VIM)。版本分两代:老 2.1 仍被广泛引用,现行 3.x 系列按版本发布图(qudt.org/3.1.4/qudt-all 这样的 URI)。

要点说明
双轨建模同一套词表提供 OWL 与 SHACL 两种 schema——选一种就用到底,别混引两套定义
命名空间qudt:(schema)· unit:(单位)· quantitykind:(量类)· qkdv:(量纲向量)· sou:(单位制)· soqk:(量类制)
工具官方 SPARQL endpoint(qudt.org/fuseki)与 GraphQL 引擎;GitHub qudt-public-repo,CC BY 4.0
03数据模型 · 三件套与两种写法 PART 2 · THE QUANTITY PATTERN

核心模式叫 Quantity Triad:一个 qudt:Quantity 回答「测什么(量类)、值多少、什么单位」。简单场景一条龙,要多套单位就把「值 + 单位」拆成 qudt:QuantityValue 节点。

# 简单写法:值和单位直接挂在 Quantity 上 ex:温控器读数 a qudt:Quantity ; qudt:hasQuantityKind quantitykind:ThermodynamicTemperature ; qudt:hasUnit unit:DEG_F ; qudt:value "72.0"^^xsd:float . # 多套单位写法:同一量,单位各表 ex:温控器读数 qudt:quantityValue ex:读数_华氏 , ex:读数_开氏 . ex:读数_华氏 a qudt:QuantityValue ; qudt:hasUnit unit:DEG_F ; qudt:value "72.0"^^xsd:float . ex:读数_开氏 a qudt:QuantityValue ; qudt:hasUnit unit:K ; qudt:value "295.37"^^xsd:float .
构件一句话
qudt:Quantity一次「量了什么」的完整陈述
qudt:QuantityValue值 + 单位的封装节点,可一量多值
qudt:Unit单位个体(unit: 词表);每个单位至少关联一个量类
qudt:QuantityKind量类:回答「这测的是什么的量」(长度、热力学温度、力……)

04单位词表 · 命名就是语法 PART 2 · UNIT VOCABULARY

unit: 里的 IRI 按固定拼法生成,读 IRI 就知道单位长相——这是 QUDT 最省心的设计,也是最容易写错的地方:

拼法例子读法
基本单位unit:M · unit:SEC · unit:KiloGM · unit:A米、秒、千克、安培——大小写敏感,千克就是这么拼
前缀缩放unit:CentiM · unit:KiloN · unit:MilliGRAY前缀词拼在基础单位前:厘米、千牛、毫戈瑞
组合单位unit:KiloGM-M-PER-SEC2 · unit:W-PER-M2-K4连字符拼接,PER 表「每」,数字表幂:kg·m/s²、W/(m²·K⁴)
机器可读码qudt:ucumCode桥接 UCUM 编码体系(医疗等领域的单位标识)
DEPRECATED 词表里有少量弃用单位,查询时先 FILTER NOT EXISTS { ?u qudt:deprecated true } 过滤,别把弃用个体写进数据。
05换算 · 乘数与偏移两个数 PART 2 · CONVERSION

每个单位自带两个换算参数,全部换算都是机械算术:

conversionMultiplier 乘数

  • 换到 SI 对应单位要乘的数:inch = 0.0254 m
  • 前缀单位同理:CentiM = 0.01 × M

conversionOffset 偏移

  • 温度这类「有零点偏移」的单位才需要:换算 = 乘以乘数再加偏移
  • 只有偏移的单位另配 SN(科学计数)孪生属性

前缀与基础单位的关系在 schema 里有正式建模:qudt:Prefix(分 DecimalPrefix / BinaryPrefix 二子类)通过 qudt:prefix 挂到缩放单位上,缩放单位用 qudt:scalingOf 指回基础单位——所以 unit:CentiM 不是手工录的,是「centi × m」推导出来的。

06量类与量纲 · 可通约的判据 PART 3 · QUANTITY KINDS

「米和英寸能换,米和秒不能」——判据由量纲向量给出。每个量类(qudt:QuantityKind)带一条 qudt:hasDimensionVector:按 SI 七基本维加无量纲,固定顺序 A E L I M H T D(物质量、电流、长度、发光强度、质量、温度、时间、无量纲)。

量类量纲向量读法
qkdv:A0E0L1I0M1H0T-2D0长度¹ · 质量¹ · 时间⁻²力(Force)——N = kg·m/s²
qkdv:A0E0L2I0M1H0T-2D0长度² · 质量¹ · 时间⁻²扭矩与能量共用这条向量
qkdv:A0E0L0I0M0H0T0D1全零 + D1无量纲(TemperatureRatio 等)
THE TRAP · 同量纲 ≠ 可互换 扭矩和能量量纲相同,物理意义完全不同——量纲相同只是必要条件。可通约还要有精选的 qudt:specializationOf(特化,如 ThermalEnergy → Energy)或 qudt:exactMatch 链接背书。换算前查这两条边,别只比向量。
07单位制与边界情形 PART 3 · SYSTEMS & EDGES

单位聚成单位制(qudt:SystemOfUnits,如 sou: 的 SI / CGS / 英制),量类聚成量类制(qudt:SystemOfQuantityKinds);单位与量类各用 applicable* 属性互通——一个单位适用于哪些量类、一个量类适用哪些单位。

无量纲 Dimensionless

  • 量纲向量全零、D 位为 1
  • 百分比、比率、计数(CountingUnit)都在此列

无向量量类 极少数

  • 极少量类(如 VisionThresholds,仅约 7 个)没有任何量纲向量
  • 「无向量」≠「无量纲」——两类别混

09实操坑清单 PART 4 · PITFALLS
  1. 单位 IRI 大小写敏感:KiloGM 就是 KiloGM——写成 KILOGM、kilogm、Kilogram 都不是合法个体;拿不准就查 unit: 词表,别手拼。
  2. 别拿字符串挂单位:"72 °F" 这种字面量把数值和单位焊死在文本里,换算、检索、校验全废——用三件套结构。
  3. 同量纲 ≠ 可换算:扭矩与能量量纲相同但物理无关;换算前认 specializationOf / exactMatch,别只比量纲向量。
  4. 温度换算带偏移:°F ↔ K 是「乘加」不是「纯乘」——conversionOffset 别漏,否则零点全错。
  5. 查询单位先滤弃用:qudt:deprecated 为 true 的个体还在词表里,别捞进新数据。
  6. OWL / SHACL 双轨选一套:两套 schema 描述同一词表,混引定义会打架;all-in-one 图按建模方式二选一。
  7. 版本引用带 URI:2.1 与 3.x 的图 URI 不同,复现实验注明版本(如 qudt.org/3.1.4/qudt-all)。
  8. 无向量 ≠ 无量纲:极少数「无向量」量类(约 7 个)是词表留白,与全零向量的无量纲类是两回事。
10查询速查 · 官方端点怎么问 PART 4 · SPARQL RECIPES

官方 SPARQL endpoint:http://www.qudt.org/fuseki。两条最常用的问法:

# 某量类下的全部现行单位(带换算乘数) SELECT ?u ?multiplier WHERE { ?u a qudt:Unit ; qudt:hasQuantityKind quantitykind:Length ; qudt:conversionMultiplier ?multiplier . FILTER NOT EXISTS { ?u qudt:deprecated true } } # 前缀单位的根与倍率:顺 scalingOf 找基础单位 SELECT ?base ?multiplier WHERE { unit:CentiM qudt:scalingOf ?base ; qudt:conversionMultiplier ?multiplier . }
GraphQL 官网同时提供 GraphQL 引擎——前端取单位详情时比 SPARQL 更省事。
