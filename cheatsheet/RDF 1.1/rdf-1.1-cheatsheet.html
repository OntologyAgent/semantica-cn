01总览 · 一套模型,四层结构 PART 1 · OVERVIEW

RDF 1.1 = 一套数据模型 + 一组序列化语法 + 一层形式语义。先看四层怎么咬合,再逐个拆零件——从最简单的名字(IRI)开始,到图,到推理。

主线:文件层允许糖——相对 IRI、前缀缩写、a;解析后图层只剩全名。
四层各有一份规范负责:concepts 管模型与词汇,语法文档各管写法,Semantics 管推理。
本卡结构 = 本图:概览 → 词汇 → 图与语义 → 语法 → 实操。
02定位 · 文档家族与三件大事 PART 1 · THE RDF 1.1 FAMILY

RDF 是万维网上的最小数据模型:一切皆三元组。1.1 版把原本分散的文档族整成一套同日发布的推荐标准——模型只有一份(concepts),语法各管一摊,彼此可互转。

03数据模型 · 三元组与图 PART 2 · ABSTRACT SYNTAX
三个位置各有准入门槛:谓语位置只允许 IRI。IRI、字面量、空白节点统称 RDF 术语(RDF terms),规范明说它们「彼此不同且可区分」。
图是集合不是列表——重复三元组自动去重;图的真值只取决于它包含哪些三元组,与书写顺序无关。
一条三元组就是一个「句子」;一张图是一袋句子。图与图之间没有主从,只有包含(A 的图可以是 B 的子图)。
WHY TRIPLES 三元组是最小的「句子」:主-谓-宾。任何复杂结构都能拆成一袋句子——这条约束换来了无限的可拼接性:谁的图里都能引用谁的 IRI,不需要 schema 协商,不需要改表。

04词汇三兄弟 · IRI / 字面量 / 空白节点 PART 2 · RDF TERMS

IRI 国际化资源标识符

  • 长相:一段像网址的字符串,如 <http://xmlns.com/foaf/0.1/Person>、<urn:isbn:0451450523>。它是名字,不是地址——所指的东西可以根本不在网上。
  • 必须绝对(指抽象语法,即入库后图里的形态)=自带全名:写 <https://ex.com/onto/Company>,不写 onto/Company。图要搬运、合并,名字到哪儿都得指同一个东西。
  • 相对 IRI 只是具体语法的糖(Turtle 等文件格式):<onto/Company> 依 @base 拼接成全名才入库——同 HTML 的 <img src="logo.png">,写短名,工具补全。
  • 相等 = 简单字符串比较,禁止额外规范化(坑见下)。
  • fragment(#Concept)= 文档内的词条名:…/skos/core#Concept 即「SKOS 词表里的 Concept 词条」,像楼址+门牌;带不带 fragment,是两个不同的 IRI。

空白节点 blank node

  • 没有全局身份的节点,只为「存在」而存在
  • 标签(_:b1)是文档局部作用域,不持久、不可移植,不属于抽象语法
  • 两张图是否「同一张」看同构:存在双射把 bnode 对 bnode、IRI 和字面量原样对齐
  • 要跨文档引用?Skolem 化:把 bnode 换成专属 IRI
IRI 相等的坑 比较只做字符级对照——大小写差异、多余百分号编码、:80、/./、/../、Punycode 主机名,统统算不同的 IRI。互操作建议:小写 scheme/主机、去掉无谓编码、路径规范化、NFC。
术语怎么选 能指认的事物(现实或抽象)→ IRI;不关心身份、只关心「有这么个东西」→ bnode;写进句子的值 → 字面量。谓语永远是 IRI——谓语本身就是需要被定义、被复用的词汇,这也是词表(vocabulary)存在的意义。
05字面量 · 三成分与两种相等 PART 2 · LITERALS

字面量 = (词法形式, 数据类型 IRI, 语言标签?)。语言标签只允许配 rdf:langString 一个类型,且必须非空、符合 BCP 47。

形态构成示例
简单字面量无标签无类型的糖,就是 xsd:string"abc"
语言标注串语言标签 + rdf:langString"猫"@zh-CN
类型化字面量datatype IRI 指定值空间"42"^^xsd:integer
病态类型词法不在类型的词法空间内——语法合法,语义不一致,实现必须接受"abc"^^xsd:integer
非规范类型rdf:HTML / rdf:XMLLiteral:值是解析后的 DOM 片段,不保证所有实现认"<b>x</b>"^^rdf:HTML
TERM EQUALITY vs VALUE EQUALITY 词项相等:三成分逐字符一致——"1"^^xsd:integer 与 "01"^^xsd:integer 词项不同,值相同。值相等:经「词法→值」映射后落在值空间同一点。查询里的 FILTER 用值比较,去重合并用词项比较——混用是经典 bug 源。

语言标注串"猫"@zh-CN"猫"@zh-CN{"@value":"猫","@language":"zh-CN"}

07数据集 · 默认图与命名图 PART 2 · GRAPH & DATASET
数据集 = 恰一个默认图(可空)+ 若干「(图名, 图)」对。三元组自己不分家,分家靠装进哪个图。
空白节点可以横跨多张图共享;图名「不要求指称那张图」——配对是语法行为,不是语义命名。
给查询引擎喂数据集时若它只收单图,默认取默认图;SPARQL 1.1 的 GRAPH 关键字在命名图之间切换。
规范 vs SPARQL 本规范允许空白节点当图名;SPARQL 1.1 只认 IRI。跨系统交换带 bnode 图名的数据集,先 Skolem 化。
08语义一瞥 · 相等、蕴含与病态 PART 2 · SEMANTICS GLANCE
概念一句话
图同构存在双射:bnode↔bnode,IRI 与字面量原样对齐,三元组一一对应——这是「同一张图」的判据
简单蕴含G 蕴含 H ≈ H 的某同构是 G 的子图——最弱的推理,不需要任何 schema 知识
RDF 蕴含加上 rdf:_n↔rdfs:member 等少量公理后的推理(细则在 Semantics 文档)
RDFS 蕴含类/属性层级、domain/range 全部生效(见 PL.02 的推理规则)
病态字面量词法不在类型的词法空间:图合法、语义不一致;实现必须照单全收,不许悄悄改写
图合并多图并成一张 = 三元组集合并集;同名 bnode 在合并后视为同一节点——合并前想清楚 bnode 归属
数据集的语义规范刻意不定义命名图的形式语义(只给了语法);理论讨论见 WG Note《On Semantics of RDF Datasets》

13rdf: 命名空间 · 核心词汇总表 PART 3 · RDF VOCAB

命名空间 http://www.w3.org/1999/02/22-rdf-syntax-ns#。定义散在 RDFS 1.1 与 Concepts 两处,这里按用途归拢。

类型系统
术语定义
rdf:type声明「资源是某类的实例」;domain rdfs:Resource,range rdfs:Class
rdf:Property「属性」这一类资源的类
rdf:langString / rdf:HTML / rdf:XMLLiteral语言标注串 / HTML 片段 / XML 片段;后两个非规范,值是 DOM 片段
具体化 · 说到「这句话」本身
术语定义
rdf:Statement「陈述」的类:某次三元组使用所对应的事物,不是三元组类型本身
rdf:subject / rdf:predicate / rdf:object从 Statement 指回三元组的三个成员;domain 都是 rdf:Statement
容器(开放)与列表(封闭)
术语定义
rdf:Bag / rdf:Seq / rdf:Alt无序袋 / 有序列 / 备选;形式上三者同构,区别只在约定

16互操作细节 · IRI 卫生与 Skolem 化 PART 4 · INTEROP

IRI 非规范形态 发出去之前消灭它们

  • 大写 scheme / 主机名
  • 多余的百分号编码、小写 HEX
  • 显式 :80 / 空路径
  • /./ 与 /../ 未消解
  • 非 NFC 字符、Punycode 主机

Skolem 化 bnode → IRI

  • 把空白节点换成数据集内唯一的生成 IRI
  • 约定用 /.well-known/genid/ 路径或 urn:uuid:,表明「这不是真资源」
  • 换完之后,跨文档引用、去重、图合并都有据可依

18实操坑清单 PART 4 · PITFALLS
  1. 空白节点标签不是标识符:换一份文档就换了含义;要跨文档引用一律 Skolem 化成 IRI。
  2. IRI 比较禁止规范化:…#A 与 …#a、%7E 与 ~ 都是不同资源;发 IRI 前先自规范。
  3. 词项相等 ≠ 值相等:"1"^^xsd:integer 与 "01"^^xsd:integer 去重时是两条。
  4. 语言标签统一小写:值层面大小写无意义,但词项相等逐字符比对——"x"@EN 与 "x"@en 是两条。
  5. 图名不指称图:别把「图 IRI」当资源描述的主语,除非你另外声明它指什么。
  6. rdf:li 只活在 RDF/XML 里,解析后变 rdf:_n;Turtle/SPARQL 里写它无效。
  7. 容器开放、列表封闭:允许别人补成员用 Bag/Seq,数据结构定死用 List。
  8. rdf:HTML / rdf:XMLLiteral 非规范:跨库可能不识别,交换场景慎用。
  9. N-Triples ⊂ Turtle ⊂ TriG 的方向记牢:解析器往大兼容,反向不成立。
  10. fragment 的语义跟着媒体类型走:同一 IRI 在 HTML 视图和 RDF 视图里指向的东西要约定一致。
