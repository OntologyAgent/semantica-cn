01总览 · 十二年来最大一次进化 PART 1 · OVERVIEW

RDF 1.2 的三件新事:三元词项让句子可被引用,方向性标签给文字方向上户口,版本声明让解析器知道规则。1.1 的模型与语法全部保留,旧数据原样合法。

主线:四件新特性全部向后兼容——旧数据原样合法,新能力按需启用。

02定位 · RDF 十二年来最大一次进化 PART 1 · POSITION

RDF 1.1 发布十二年后的换代:吸收整个 RDF-star 社区方案(三元组当宾语),补上双向文字的方向,给文件加上版本声明。由 RDF & SPARQL 工作组推进,配套 SPARQL 1.2 同步演进。

为什么是现在 MOTIVATION

  • 溯源与置信度标注是图数据库的头号刚需,RDF-star 社区方案已跑了多年
  • RTL 文字(希伯来/阿拉伯)在 1.1 里无处声明方向,渲染端各自猜
  • 多语法共存需要显式的版本握手

原则 COMPATIBILITY

  • 所有 1.2 语法向后兼容 1.1——老文件零改动
  • 新特性按需启用,声明版本才生效
  • 抽象语法只加不改:RDF 术语仍是 IRI/字面量/空白节点(三元词项是字面量之外的第四类「词项」)

04三元词项 · 给「这句话」一个身份 PART 2 · TRIPLE TERMS

「谁在什么时候说了 `爱丽丝任职某公司` 这句话」——信息本身是一条三元组,要对它再说话,1.1 里只能靠具体化四件套或 Reification 私货。1.2 直接让三元组坐进宾语位。

三元词项(triple term):一条三元组作为宾语出现,但不因此成立——它是可被谈论的「命题」。
具体化三元组(reifying triple):主语(reifier)经 rdf:reifies 指向三元词项。当词项恰好等于一条已断言的三元组,这个模式叫 triple annotation——最常见用途:给断言挂出处、时间、置信度。
# 全写形式:<<( … )>> 是三元词项,rdf:reifies 普通地写在谓语位 _:anno rdf:reifies <<( :e38 :jobTitle "Designer" )>> . _:anno :accordingTo :hrDept ; :asOf "2026-01-01" . # 糖一:<< s p o >> = 断言该三元组 + 生成匿名 reifier 指向它 << :e38 :jobTitle "Designer" >> :accordingTo :employee22 . # 糖二:~ 命名 reifier;{| |} 注解块 = 断言 + 具体化 + 挂属性,三合一 :alice :name "Alice" ~ :t1 {| :statedBy :bob ; :confidence 0.9 |} . # 溯源实战:同一句 proposition,两路人马各自背书 VERSION "1.2" :drugX :treats :diseaseY ~ :claimA {| :source :paper2024 |} . :drugX :treats :diseaseY ~ :claimB {| :source :registry ; :asOf "2026-06-01" |} . # 两个 reifier 指向同一命题——多人背书,互不干扰

05方向的语义 · 透明性与同一性 SEMANTICS OF << >>

透明性 transparent

  • 三元词项里的术语照常指称自己的资源
  • 查询时可以「看穿」词项匹配内部三元组
  • 对比:1.1 具体化四件套只是四个普通节点,毫无透明性

同一性 identity

  • 三元词项按三元组逐项相等判定同一
  • 同一命题可以有多个 reifier(多人背书)
  • 一个 reifier 也可具体化多条命题——比 RDF-star 草案更灵活
与老具体化的关系 rdf:Statement / subject / predicate / object(引 PL.01 §13)仍有效但继续边缘:三元词项才是 1.2 的正路。SPARQL 1.2 同步获得查询三元词项的能力。

06方向性语言标签 · 文字的方向有了户口 PART 2 · DIRECTIONAL LANGTAGS

希伯来、阿拉伯、波斯文在混排环境里必须声明书写方向。1.2 给语言标注字面量加第三个部件:base direction,类型升级为 rdf:dirLangString。

# Turtle 1.2:语言标签后接 -- 方向,只许 ltr / rtl "HTML היא שפת סימון."@he--rtl . "That Seventies Show"@en-us--ltr . # 没写方向的语言标签仍是 rdf:langString,行为与 1.1 一致 "chat"@fr .
字面量形态类型部件
简单串xsd:string词法形式
语言标注rdf:langString词法形式 + 语言标签
方向性语言标注rdf:dirLangString词法形式 + 语言标签 + base direction
方向是元数据,不是内容 base direction 由渲染端消费:数据模型只负责携带,不参与字符串比较——同词法同标签、方向不同的两个字面量是否「相等」,以规范的定义为准,使用前查 Concepts 细则。双向文字算法(BiDi)本身是 Unicode 的事,别在数据层硬排。
07版本声明 · 告诉解析器「我是谁」 PART 3 · VERSION DECLARATION
# 文档内:SPARQL 风格(无点)或老风格(有点),二选一 VERSION "1.2" :s :p "نص عربي"@ar--rtl . # HTTP 头:内容协商时声明 Content-Type: text/turtle; version=1.2
标签含义
"1.2"完整 1.2(可用三元词项、方向标签)
"1.2-basic"1.2 但不含三元词项
"1.1"声明兼容 1.1(规范建议别再标)
提示而非强制 规范明说版本指令只是 hint;但用到方向标签或三元词项时必须声明版本,否则不构成合法的 1.2 文档。

升级清单 · 1.1 仓库存量怎么动
  1. 审计语言标签:全库扫一遍标签大小写与子标签(zh vs zh-CN),统一规范写法——1.2 下不再有侥幸。
  2. 盘点双向文字:哪些字面量需要方向?补 --ltr/--rtl,渲染端同步读取。
  3. 决定档位:上游只认 Basic 就别急着用三元词项;能用 PROV-O 表达的溯源,先不迁移。
  4. 加 VERSION:写新特性的文件全部带上版本声明;HTTP 出口补 media type 参数。
  5. 回归测试:用 1.1 语料喂 1.2 解析器,确认零差异;再用最小 1.2 样例验证工具链。

10实操坑清单 PART 4 · PITFALLS
  1. 状态先看清:截至 2026-10,Concepts 在 CR、语法件在 WD——生产系统引用前先查最新进度,别把草案当标准。
  2. 用三元词项或方向标签,文档必须声明版本(VERSION "1.2" 或 HTTP 参数)。
  3. << s p o >> 是「断言 + 具体化」的糖;<<( s p o )>> 只引用不断言——两者差一个括号,语义天差地别。
  4. 一个命题可挂多个 reifier、一个 reifier 可背书多条命题——别按「一一对应」建模背书关系。
  5. 方向标签只有 ltr / rtl 两值,默认无方向;只有真有双向混排问题才用,否则平添比较负担。
  6. 语言标签大小写合一后,1.1 时代按大小写区分的索引、去重逻辑要重审。
  7. Basic 档(1.2-basic)不收三元词项——下游只认 Basic 时,新特性数据要降级交换。
  8. 老具体化四件套与新三元词项是两套体系,同一份图里别混用表达同一件事。
  9. 工具支持仍在铺开:升级解析器/图库前,先用 1.2 特性的最小样例做冒烟测试。
  10. 向后兼容是承诺:1.1 老文件不用改——迁移压力只在你决定用新特性那一刻才出现。
