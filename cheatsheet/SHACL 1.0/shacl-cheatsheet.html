02定位 · 给 RDF 数据上「合同」 PART 1 · POSITION

开放世界的 RDF 缺一样东西:约束。Shapes Constraint Language(SHACL,读作「shackle」)用一份 RDF 写的「形状图」去校验另一份「数据图」,输出结构化报告——通过、警告、不通过,条条有据。

KEY POINT SHACL 1.0,W3C Recommendation 2017-07-20。语法就是 RDF(shapes graph 本身是合法 RDF 图);校验期间两份图都必须保持不可变。命名空间 sh: = http://www.w3.org/ns/shacl#。与 OWL 的分野一句话:OWL 是推理,SHACL 是校验——违反约束报错,而不是默默推出新类型。

SHACL 管 VALIDATION

  • 数据长什么样才合格:必填、类型、取值范围、基数
  • 封闭世界检查:sh:closed 说「除此之外不许有」
  • 输出机器可读的验证报告

SHACL 不管 OUT OF SCOPE

  • 推断新事实(那是 RDFS/OWL 的活,PL.02/PL.04)
  • 限定词表内容管理(那是 SKOS 的活,PL.03)
  • 「为什么这么建模」——它只验收,不指导

03结构模型 · 节点形状与属性形状 PART 1 · STRUCTURAL MODEL
焦点节点(focus node)由目标选出;值节点(value nodes)是焦点节点沿 sh:path 走到的节点。节点形状的值节点就是焦点节点自己。
两类形状互斥:有 sh:path 的就是属性形状,没有的就是节点形状——别混着用。
path 不只是 IRI sh:path 接受 SPARQL 属性路径:序列 (ex:parent ex:parent)、反向 [ sh:inversePath ex:parent ]、交替 sh:alternativePath——校验祖孙、反向引用一行搞定。

04约束组件全表 · SHACL Core 的弹药库 PART 2 · CORE COMPONENTS
组组件一句话
值类型sh:class值是某类的实例(RDFS 语义下连同继承)
sh:datatype值的数据类型(xsd:string、xsd:integer…)
sh:nodeKind值是 IRI / BlankNode / Literal / BlankNodeOrIRI…
基数sh:minCount / sh:maxCount值节点个数下限/上限(仅属性形状)
sh:qualifiedValueShape + Min/MaxCount满足某形状的值至少/至多几个(如「至少一个收件人」)
数值范围sh:minExclusive / minInclusive下界(开/闭)
sh:maxExclusive / maxInclusive上界(开/闭)
字符串sh:minLength / maxLength长度上下限
sh:pattern + sh:flags正则(XPath 正则,flags 可加 i 大小写不敏感)
sh:languageIn语言标签白名单([ "zh", "en" ])
sh:uniqueLang同一语言标签至多一个值(true)
属性对sh:equals与另一属性的值完全相同
sh:disjoint与另一属性无公共值
sh:lessThan / lessThanOrEquals本属性值严格小于(≤)另一属性值——startDate < endDate
组组件一句话
逻辑组合sh:not [shape]值节点不满足该形状
sh:and / sh:or形状列表全满足 / 至少一个
sh:xone恰好满足其一(异或)——「二选一必填」神器
sh:hasValue值里必须含某个特定值
形状引用sh:node [shape]值节点整体满足另一节点形状(嵌套复用)
sh:property挂子属性形状
封闭sh:closed true除声明过的属性外不许有其他谓语
sh:ignoredPropertiesclosed 的豁免名单(rdf:type 常在此)
枚举sh:in ( "低" "中" "高" )值必须在列表内
经典组合 · 三条最高频的形状
# 1. 必填且唯一且是字符串 [ sh:path foaf:name ; sh:datatype xsd:string ; sh:minCount 1 ; sh:maxCount 1 ] # 2. 多语言名:每个标签至多一个,语言限定中英 [ sh:path rdfs:label ; sh:uniqueLang true ; sh:languageIn ( "zh" "en" ) ] # 3. 受控字段:枚举 + 模式 [ sh:path :status ; sh:in ( "draft" "published" "retracted" ) ] [ sh:path :orcid ; sh:pattern "[0-9]{4}-[0-9]{4}-[0-9]{4}-[0-9]{3}[0-9X]" ]

07SHACL-SPARQL · 表达力不够就写查询 PART 3 · SHACL-SPARQL

Core 组件覆盖不到的约束,用 SPARQL 写。Core 实现必须忽略 sh:sparql——用它就要认准带 SPARQL 引擎的校验器。

# 自定义约束:国家必须出现在维基数据里(示意) ex:CountryShape a sh:NodeShape ; sh:targetObjectsOf :inCountry ; sh:sparql [ sh:message "国家需要 instance of (Q5) 声明" ; sh:select """ SELECT $this WHERE { FILTER NOT EXISTS { $this wdt:P31 wd:Q3624078 } } """ ] . # 预绑定变量:$this = 焦点节点;路径约束另有 $path / $value
扩展机制说明
SPARQL 约束sh:sparql + SELECT(报违规)或 ASK(报通过)
自定义组件sh:parameter 声明参数 + sh:labelTemplate + 验证器——造自己的「组件」给别人用
SPARQL 目标sh:targetSPARQL:用 SELECT 自己选焦点节点
qualified 的经典用法 · 披萨规则
# 一份披萨:至少一个非素菜配料(qualified 只数「满足形状」的值) :PizzaShape sh:property [ sh:path :hasTopping ; sh:qualifiedValueShape [ sh:not [ sh:class :VegetarianTopping ] ] ; sh:qualifiedMinCount 1 ] .
08SHACL-SHACL · 用 SHACL 校验 SHACL PART 3 · SHACL-SHACL

规范附录自带一份「元形状」:校验你的形状图本身写得对不对——组件误用、类型乱挂都逃不掉。

实用结论 上线前把形状图过一遍 SHACL-SHACL:sh:shapesGraphWellFormed 为 true 才算语法健康。形状写错不是数据错,错误会更隐蔽——这一步别省。

形状图 shapes graph

  • RDF 图,内容是形状与约束
  • 校验期间不可变
  • 可复用、可导入、可组合

数据图 data graph

  • 被校验的对象
  • 校验期间不可变
  • 与形状图可以是同一张图(不推荐混)

09实操坑清单 PART 4 · PITFALLS
  1. sh:class 看的是 rdf:type 的传递语义(RDFS 下连同子类),sh:datatype 是严格词法比对——「看着像」不等于「校得过」。
  2. 字面量 "5" 与 5 不是一回事:数据类型没对上,sh:minInclusive 直接违规——先统一数据类型再上形状。
  3. 节点形状与属性形状互斥:加了 sh:path 就变属性形状,minCount 只在属性形状里有效。
  4. sh:closed 是按谓语封闭:路径里没声明的谓语一律违规——rdf:type 记得进 ignoredProperties。
  5. 递归形状(sh:node 自我引用形成环)的行为规范未定义——设计形状层级时避免循环引用。
  6. sh:xone 是「恰好一个」,sh:or 是「至少一个」——「二选一必填」用 xone,用 or 会放过全选。
  7. 合格性是逐值判定的:一条约束违规生成一条 result,别指望报告里自动聚合。
  8. 校验期间图必须不可变:边校验边改数据的管线是未定义行为,先出报告再动数据。
  9. OWL 公理不参与 SHACL 校验——想让 sh:class 认子类,校验器得开 RDFS 推理档,或显式补类型。
  10. 形状图与数据图分开存放:混在一张图里,校验目标会把形状也「验证」一遍。
