02定位 · 把图书馆的功夫搬上 RDF PART 1 · POSITION

叙词表、分类法、标题表——图书情报界积攒了一个世纪的受控词汇,SKOS(Simple Knowledge Organization System)给它们一个 RDF 形状:概念用 skos:Concept,体系用 skos:ConceptScheme,层级用 broader/narrower,跨体系对齐用五种 match。

KEY POINT SKOS,W3C Recommendation 2009-08-18,命名空间 skos: = http://www.w3.org/2004/02/skos/core#。整个数据模型定义为 OWL Full 本体——不设形式一致性判据,违反约束的判定交给「是否导致逻辑矛盾」。RDFS 给世界分类,SKOS 给世界整理概念:一个东西可以既是 owl:Class 又是 skos:Concept,两者并不冲突。
03三个类 · 体系、概念、集合 PART 1 · THREE CLASSES
ConceptScheme 是概念的聚合体:一份叙词表、一套分类法。hasTopConcept 从体系指到顶层概念,topConceptOf 反向且同时是 inScheme 的子属性。
Collection 是「概念组袋」——把一组概念挂个名(如「乳制品」),但它不是概念:对集合写 broader 会直接造成逻辑矛盾。
三类两两不相交是 SKOS 少数的硬约束——比起 owl 一家,SKOS 的「法律」很少,但这条是真的。

05标注词汇 · 让概念开口说话 PART 2 · LABELING VOCAB
属性角色约束
skos:prefLabel首选标签——界面显示用它每个语言标签至多一个(S14);与 alt/hidden 互斥(S13)
skos:altLabel替代标签——同义词、别名、旧称「用/代」里的「代」
skos:hiddenLabel隐藏标签——只给搜索索引看,不显示拼写变体、错拼兜底
skos:notation符号编码——DDC 分类号、术语代码约定用类型化字面量;同体系内唯一是约定不是硬约束
三个都 ⊑ rdfs:label pref/alt/hidden 都是 rdfs:label 的子属性,值域是普通字面量。语言标签不是硬性要求(S14 只约束「同一标签至多一条」),但跨语言检索全靠它——实践中一律补齐。
06文档属性 · 一张 note 网撑起说明书 PART 2 · DOCUMENTATION NOTES
属性写什么
skos:note总note;下面六个都是它的子属性,语义细分
skos:definition正式定义——概念的「官方解释」
skos:scopeNote范围说明——收录什么、排除什么
skos:example用例
skos:historyNote历史沿革(概念的演变)
skos:editorialNote编者注(给后续编辑者的便条)
skos:changeNote变更记录(这次改了什么)
全都无 domain / range 文档属性刻意不加约束——note 可以挂概念、挂体系、挂集合。想让 note 结构化(如带出处、带作者),别硬塞字面量,看 SKOS-XL 的思路把 note 升级成资源,或直接用 PROV-O(PL.11)。

08SKOS-XL · 把标签升级成资源 PART 2 · SKOS-XL

为什么要 XL label as resource

  • 普通标签是字面量——查不了「谁在用这个词形」
  • XL 把标签变成 skosxl:Label 资源:可挂出处、版本、语料统计
  • 同一词形被多概念共用时,有了统一的「词形节点」

怎么用 Appendix B

  • skosxl:prefLabel / altLabel / hiddenLabel:值是 Label 资源而非字面量
  • 与 SKOS 核心标注并存,共同约束照搬(每语言一 pref 等)
  • 机器互操作注意:很多工具只认核心标注,XL 数据要回落导出

09语义关系 · 层级与关联的完整矩阵 PART 3 · SEMANTIC RELATIONS
属性方向性要点
skos:semanticRelation—所有语义关系的祖先;domain = range = skos:Concept
skos:broader⟷ narrower(互逆)不传递——只断言直接上级;⊑ broaderTransitive
skos:narrower⟷broader 的正式反向(owl:inverseOf)
skos:related对称横向关联;不传递;与 broaderTransitive 不相容(S27)
skos:broaderTransitive / narrowerTransitive互逆传递;约定只用于推理不当断言——查询时展开,落盘时少写
skos:hasTopConcept / topConceptOf互逆体系 ↔ 顶层概念;topConceptOf ⊑ inScheme
skos:inScheme—概念属于哪些体系;一个概念可属多个体系
S27 的后果 related 与 broaderTransitive 不相容:x related y 且 x(传递地)y,图即矛盾。直白的层级别写 related,横向的联想别进 broader 链——叙词表的「属分」与「参」在 SKOS 里真的互斥。
10映射词汇 · 跨体系对齐的五种 match PART 3 · MAPPING VOCAB
属性对称传递何时用
skos:exactMatch是是两概念可互换使用(跨体系「同一个」)
skos:closeMatch是刻意不明显相关但不可互换;不传递是为防「连锁误传」
skos:broadMatch⟷ narrowMatch—对方概念是本概念的上位(⊑ broader)
skos:narrowMatch⟷—broadMatch 的正式反向
skos:relatedMatch是—横向相关(⊑ related)
子属性链的推理后果 五个 match 都是 mappingRelation 的子属性,而 mappingRelation ⊑ semanticRelation——断言一条 match,自动推出对应语义关系与 Concept 类型。exactMatch 与 broadMatch/relatedMatch 不相容(S46)。
映射实战五步
  1. 拉候选:标签相似度 + 结构相似度(各自的 broader 邻域)双路召回,人工只看短名单。
  2. 对定义:比 definition 和 scopeNote,不看名字看范围——收录边界不同就别 exact。
  3. 定级别:可互换 → exact;方向明确 → broad/narrow;沾边 → related;拿不准 → close。
  4. 记出处:映射本身是一条断言,配 dcterms:source 或 PROV-O(PL.11)记录谁、何时、凭什么。
  5. 留维护钩子:词表会改版——映射挂版本化的概念 IRI,别挂会漂移的标签。
11集合 · 不是概念的「组袋」 PART 3 · COLLECTIONS
机制说明
skos:Collection命名的概念组(如「乳制品」「不善飞行的鸟」);与 Concept / ConceptScheme 均不相交
skos:memberdomain Collection,range = Concept ∪ Collection——集合可以套集合
skos:OrderedCollection有序变体;memberList(range rdf:List)是函数属性,且蕴含每个成员的 member
语义关系禁区集合上写 broader/related 会矛盾——关系的 domain/range 是 Concept,集合不是

13与 RDFS / OWL 共存 · 分工不打架 PART 4 · WITH RDFS/OWL

什么归 SKOS terms

  • 整理「人们怎么说」:概念、别名、层级、跨表映射
  • 叙词表、分类法、标题表的 RDF 化

什么归 RDFS / OWL logic

  • 形式类与属性:实例判定、限制、推理
  • 一个 IRI 同时是 Concept 和 Class 是合法的,但要想清楚两边各答什么问题
工程取向 领域本体(是什么)走 RDFS/OWL;术语体系(怎么叫)走 SKOS;两者用 annotation 或 seeAlso 桥接,别用推理硬绑。
14SPARQL 查询速查 · 词表的日常问法 PART 4 · SPARQL RECIPES

15形式约束清单 · SKOS 少数几条硬法 PART 5 · FORMAL CONSTRAINTS
编号约束
S9ConceptScheme 与 Concept 不相交
S13prefLabel / altLabel / hiddenLabel 两两不相交

判定的口径 这些约束的违反定义为「导致逻辑矛盾」——用带 OWL 推理的引擎能查出来;普通 RDF 存储不会拦你,入库前自查或用 SKOS 校验工具。
16实操坑清单 PART 5 · PITFALLS
  1. broader 不传递:要「所有后代」查询时展开 broaderTransitive(+ 路径),别在数据里手写传递链。
  2. Transitive 系按约定只推不断言:落盘写传递闭包既冗余又容易过期。
  3. prefLabel 每语言一条——双语同义词请分流到 altLabel,别塞两个 pref。
  4. 同一字符串不能同占 pref 与 alt(S13):改首选时记得把旧 alt 删掉。
  5. 层级走层级、联想走 related:同一对概念两条都写,若闭包相连即矛盾(S27)。
  6. Collection 不是 Concept:对集合写 broader/related 直接矛盾(S37 + 关系的 domain/range)。
  7. exactMatch 传递、closeMatch 刻意不传递——「大概像」的断言连成链会放大错误,规范替你踩了刹车。
  8. 映射要留出处:SKOS 不替你管 provenance,映射断言请配 PROV-O(PL.11)或至少 dcterms:source。
  9. notation 同体系唯一是约定:入库查重自己做,规范不拦。
  10. SKOS 本体在 OWL Full:推理机选档要小心,别在 OWL DL 严格模式下硬加载。
