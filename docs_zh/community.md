Semantica 在完全开放的状态下构建，贡献者中有来自多个领域的研究者、工程师和一线从业者。无论是提交缺陷报告、分享项目，还是评审 PR(Pull Request)——你都是这个生态的一分子。


## 获取帮助

- [GitHub Issues](https://github.com/semantica-agi/semantica/issues)：提交带完整上下文的缺陷报告和功能请求。
- [GitHub Discussions](https://github.com/semantica-agi/semantica/discussions)：提问、分享想法、讨论设计决策。
- [Pull Requests](https://github.com/semantica-agi/semantica/pulls)：浏览现有的贡献，或提交你自己的。
- [安全问题](https://github.com/semantica-agi/semantica/security/advisories/new)：私下报告漏洞（切勿发在公开 issue 里）。


## 社区准则

我们遵循[贡献者公约行为准则](https://github.com/semantica-agi/semantica/blob/main/CODE_OF_CONDUCT.md)。社区建立在四条原则之上：

- **尊重**：无论经验深浅，都以善意和耐心对待每一个人
- **包容**：欢迎一切背景、领域和方法
- **协作**：共同打磨更好的方案，而不是在路线上互相较劲
- **学习**：开放地分享知识，大胆提问，帮助他人成长

如遇不可接受的行为，请开一个带 `[CoC]` 前缀的 GitHub issue。每一份报告都会得到认真处理。


## 贡献方式

贡献没有唯一正确的方式。选一条适合你技能和时间的路径：

### 代码

- 修复打上 [`good-first-issue`](https://github.com/semantica-agi/semantica/labels/good-first-issue) 标签的开放缺陷
- 添加新功能或新集成
- 优化性能，或重构现有模块

### 文档

- 修正指南中的笔误，让表述更清晰
- 为 API 参考补充示例
- 撰写领域相关的 cookbook notebook

### 测试

- 为尚未覆盖的模块补充测试
- 复现并确认已报告的缺陷
- 提升测试在各平台上的稳定性

### 社区

- 在 issue 和讨论区回答问题
- 评审开放的 pull request
- 在 GitHub Discussions 分享你的 Semantica 项目

完整的开发工作流见[贡献指南](./contributing-guide.md)。
