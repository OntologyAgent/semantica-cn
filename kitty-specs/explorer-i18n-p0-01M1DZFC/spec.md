# Specification: Explorer 中文界面 P0

**Mission**: `explorer-i18n-p0-01M1DZFC` · software-dev · PR-bound
**Branch contract**: 规划与实现均在 `feature/explorer-i18n-p0`，mission merge 时回 `main`
**Date**: 2026-09-01

## Overview

Knowledge Explorer（Semantica 的 Web 客户端）目前全部界面文案为英文硬编码，中文用户使用门槛高。本 mission 落地国际化改造的 P0 阶段：为应用建立中英双语文案能力与用户可控的语言开关，覆盖全局框架文案（主导航、首屏、子视图页签、连接状态、工作区壳层、错误提示）。工作区内部正文（约 1,200 条）不在本期范围，将由后续批次按同一机制分批补齐。

设计输入：用户已批准的 P0 技术计划（Claude Code plan mode，2026-09-01），三个方向性决策经用户逐项确认（见"决策记录"）。

## User Scenarios & Testing

### 主流程（语言切换）

中文浏览器用户首次打开 Explorer → 主导航、首屏、页签、连接状态全部显示中文 → 点击语言开关切换到英文 → 框架文案立即变为英文（页面不刷新）→ 刷新页面 → 仍为英文 → 切回中文并重开应用 → 保持中文。

### 异常路径

- 后端不可达：连接状态提示（连接中/在线/后端不可达）以当前所选语言显示。
- 工作区渲染出错：错误边界的说明文字以当前所选语言显示。

### 边界情况

- 浏览器禁用本地存储（隐私模式、清空站点数据）：语言偏好无法持久化时回落到浏览器语言自动检测，切换功能本身不受影响。
- 非中文浏览器语言：一切可见行为与改造前完全一致（全英文）。

## Requirements

### Functional Requirements

| ID | Requirement | Status |
| --- | --- | --- |
| FR-1 | 用户点击语言开关后，P0 范围内的全局框架文案立即以目标语言重新显示，全程无需刷新页面 | Clear |
| FR-2 | 用户重新打开应用（刷新或重开浏览器）后，界面显示其上次选择的语言 | Clear |
| FR-3 | 首次访问且无已存偏好时：浏览器语言为中文(zh\*)则显示中文框架文案，否则显示英文 | Clear |
| FR-4 | P0 范围文案全覆盖中英双语：六项主导航（名称+描述）、各工作区子视图页签、连接状态标签、首屏（指标卡、行动卡、进入按钮）、工作区壳层（标题/副标题/眉题/页签）、加载回退提示、错误边界说明 | Clear |
| FR-5 | 任一译文缺失时，该处显示英文原文，不得显示键名或空白 | Clear |
| FR-6 | 中文与英文文案资源的键集合必须一致；任一侧缺键在构建（类型检查）阶段即失败 | Clear |
| FR-7 | 页面语言属性（`<html lang>`）与浏览器标签页标题随当前语言同步更新 | Clear |
| FR-8 | 提供命令行脚本，报告中文译文相对英文基准的过期状态（fresh/stale/orphan）及缺失键清单，机制与 `tools/i18n/zh_status.py` 一致 | Clear |
| FR-9 | 自动化端到端测试可通过预置机制固定为英文运行并全部通过 | Clear |

### Constraints

| ID | Constraint | Status |
| --- | --- | --- |
| C-1 | 零侵入边界：允许修改的上游文件仅限前端应用入口、根组件、错误边界组件、前端依赖清单（含锁文件）、端到端测试的语言预置行；其余改动必须以新增文件落地 | Clear |
| C-2 | 禁触区：不得修改 Python 后端（explorer 服务端）、静态入口 HTML、构建配置；后端返回的错误消息原文保持英文，仅前端包装文案可译 | Clear |
| C-3 | 语言状态必须经响应式机制传播到已渲染界面（应用启用了编译期自动记忆化，可变全局变量不可靠） | Clear |
| C-4 | 中文术语以 `docs/zh/glossary.md` 为唯一基准；产品名（Ontology Hub 等）按术语表保留英文 | Clear |
| C-5 | 本期仅中英两种语言；资源组织方式须允许后续新增语言而无需重构 | Clear |
| C-6 | 新增依赖仅限 i18n 用途（i18next、react-i18next），须与 React 19 兼容 | Clear |

## Success Criteria

1. 浏览器语言为中文的新用户首次打开应用，P0 范围文案 100% 显示中文（逐屏走查 0 处英文残留）。
2. 点击语言开关后 P0 范围文案 100% 即时切换，无需刷新；重开应用后语言保持。
3. 英文偏好用户的可见界面与改造前完全一致（对比走查 0 处差异）。
4. 全部既有自动化测试通过；中文术语与术语表一致率 100%；译文过期检查脚本对本期产出报告 fresh。

## Key Entities

- **语言偏好**：用户的界面语言选择，仅存于浏览器本地。
- **文案资源**：以稳定键组织的界面文案集合，中英各一份；英文为键基准。
- **过期状态记录**：中文资源内记录翻译时的英文基准版本号，供过期检查脚本比对（fresh/stale/orphan）。

## 决策记录（DIRECTIVE_003）

| 决策 | 结论 | 理由与必须保持为真的约束 |
| --- | --- | --- |
| 实现策略 | 经典抽取式（字面量 → 按键取译文） | 长期类型安全、可维护；代价是上游组件文件改动带来的合并成本，由 C-1 边界收敛到最小集合 |
| 技术选型 | 引入 i18next + react-i18next | 生态标准（复数/插值/类型化），React 19 兼容；自研方案被否以避免重复造轮子 |
| 本期范围 | P0：基础设施 + 全局框架 | 与 docs/zh 的 P0→P3 分批节奏一致；工作区正文量大（~1,200 条），分批降低 review 与回归风险 |

## Assumptions

- 语言偏好仅存浏览器本地，不做账号级同步。
- 日期/数字格式沿用浏览器默认区域行为，本期不显式接管。
- 端到端测试固定英文属最小上游测试改动，需在 PR 描述中显式说明。
- 各工作区壳层文案目前与 `App.tsx` 中的页签配置同源；若个别壳层文案在工作区组件内部，仅抽取其壳层标签，正文不动。

## Out of Scope（后续路线，非本期目标）

- P1：GraphWorkspace 壳层与工具栏文案（约 290 条，含端到端测试与文案解耦）。
- P2：OntologyWorkspace（约 350 条）及其余工作区正文分批翻译。
- P3：注册表审计 summary 的渲染时翻译、后端错误消息的错误码映射。
