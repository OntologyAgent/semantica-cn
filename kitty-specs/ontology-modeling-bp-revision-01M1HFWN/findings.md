# Research Findings: 本体建模最佳实践修订

> 综合五路证据（书稿 / StockInsight / 官方 docs / cookbook+examples / 现有文档审计）得出的修订决策日志。
> 每条结论引用 `research/evidence-log.csv` 的证据行 ID。证据→结论的对应可逐条回查。

## 主要发现

### F1 现有文档的方法论骨架成立，但 29 句话表必须整体重排

**证据显示**：现有文档的章节结构与书稿方法论逐节对应（四铁律 ↔ 准入四标准 E-BK-03；3.6 ↔ 双大模型协同 E-BK-05；3.8 ↔ 场景化测试 E-BK-07），但 29 句话表与重扫书稿图 6-1 大面积不符——枚举数对不上、类目错归、语义错配、四处「原图裁切」占位（E-AU-F1）；书稿权威清单为 7 类 2+7+3+1+5+4+7=29 句（E-BK-01）。
**我们得出**：方法论骨架保留（FR-008），29 句话表以 E-BK-01 逐句重排为修订的第一优先级；书稿 7 处转写痕迹（E-BK-F）在引用时不扩散。
**备选解释**：旧表或许是「有意的工程化改写」而非讹误——被「53–56（原图裁切）」占位与类目错归排除：有意的改写不会留占位符。
**置信度**：高。

### F2 现有代码示例约八成不可直接运行，必须以三源已验证调用重写

**证据显示**：11 处 API 用法实测不成立（E-AU-T01/T06/T07/T08/T09/T10/T12/T16/T18/T19/T21），横跨抽取、归一、冲突、去重、建模、建图、校验、导出各阶段；跑通的是 StockInsight 另一套组合（E-SI-01/E-SI-02）。
**我们得出**：全部代码示例按「StockInsight 实测（0.6.7）> cookbook 已验证 > 官方 reference」优先级重写（plan IC-02）；最小可跑链路必须真实执行（NFR-001）。
**备选解释**：文档可能面向某个旧版本 API——被 .venv 同为 0.6.7 系的 ImportError 实测排除（E-AU-T01）。
**置信度**：高。

### F3 「书稿目标标准」与「Semantica 实际实现」必须显式分离，这是本次修订的灵魂改动

**证据显示**：书稿方法论建立在 W3C 全家桶上（E-BK-02），但 Semantica 全库无 SWRL/OWL-S/ODRL 实现（E-AU-T24），四种属性逻辑特征无任何处理且 to_shacl 不生成（E-AU-T19），TEMPORAL/LOGICAL 冲突未实现于 ConflictDetector（E-DC-02）；「四剑客」实为 Protégé/OWL 推理机能力（E-BK-06 + E-AU-T19）。
**我们得出**：文档集必须有专门一篇（篇4）做「目标标准 vs 实际实现」对照：每项缺口给出证据位置与可行替代（Reasoner 规则代 SWRL、SHACL+GraphValidator(schema) 代四剑客、PolicyEngine+决策留痕近似 ODRL）；正文不再假装存在对应 API。
**备选解释**：也许未来版本会实现这些标准——无法排除，但文档以 0.6.7 实装为准并注明版本（E-DC-06），未来变化由版本管理应对。
**置信度**：高。

### F4 官方文档自身有 11 处不一致，版本滞后于实装

**证据显示**：reference 与 concepts/quickstart/modules 在阶段数、API 名、返回类型上互相矛盾（E-DC-05）；quickstart 标注 0.5.0 而 .venv 实测 0.6.7（E-DC-06）；StockInsight 实测 detect_conflicts(graph) 在 0.6.7 可用而 reference 未载（E-SI-02 vs E-DC-05）。
**我们得出**：文档所有 API 表述采用统一裁定规则——实测 > reference > 其他文档；篇4 收录裁定表，帮读者避免同样的坑。
**备选解释**：docs 也许描述的是另一条产品线——被同仓库 CHANGELOG 与模块行为一致排除。
**置信度**：高。

### F5 cookbook 蕴含官方模块文档未覆盖的 17 个直接相关实践模式

**证据显示**：本体即代码/业务键 ID/关联类物化+快捷边/完整 URI/SHACL 双工件/CQ 前置/三件套/版本管理（E-CB-01/E-CB-02）；源可信度+双策略消解+人工调查、去重完整集、审计级溯源四元组（E-CB-03）；span 建边/消解重映射/验证门禁/种子先行（E-CB-04）；官方编排样板（E-CB-06）。
**我们得出**：按阶段织入篇2（plan IC-05），每个模式回答「解决本阶段什么问题」；间接相关（时态/Datalog RBAC/GraphRAG，E-CB-05）作延伸阅读链接。
**备选解释**：这些模式可能过时——被 capability_gap example（最新 e2e 基线）同样使用排除。
**置信度**：高。

### F6 阶段契约缺口是系统性的，需要「四要素模板 + 变量流总图」双管齐下

**证据显示**：审计 D 节逐阶段列出缺口——无变量级数据流、3.3 输入 objects 与 3.4 输入 facts 来源未定义、3.6 审计回路与 3.8 失败修复回路缺失、四铁律退回只给模块名（E-AU-D）；官方模板给出正确顺序参考（E-DC-04）。
**我们得出**：篇2 每阶段固定「输入/输出/前置依赖/后续流向」四要素小节 + 开篇变量流总图（plan IC-03），阶段顺序对齐官方链路（E-DC-04 + E-DC-02 的「先冲突后合并」）。
**备选解释**：契约缺口或许只是行文简洁的取舍——被「校验点无法替代数据流约定（3.2 对象与 3.4 dict 类型断档直接导致示例跑不通）」排除。
**置信度**：高。

### F7 领域解耦是可达成的：示例换案例 + 每阶段适配指引

**证据显示**：现有示例写死荔枝植保（E-AU-E）；StockInsight 有同构的完整业务面（规则/权限/溯源/决策，E-SI-01/E-SI-03）；书稿方法论本身领域无关（荔枝只是 demo 场景，E-BK-01~07 的方法论述均不依赖农业）。
**我们得出**：示例整体替换为 StockInsight 投资案例（FR-004），每阶段末尾「换领域时怎么适配」短段（FR-009）；StockInsight 未落地部分（std 契约）如实标注「规划中」（E-SI-03）。
**备选解释**：双案例并行（荔枝+投资）——被「互引与体量约束（≤5 篇）」排除，单案例贯穿更清晰。
**置信度**：高。

## 局限性（Limitations）

1. **文档覆盖不全**：docs/guides/ 下 8 篇（graphrag、shacl-validation、context-graphs、decision-intelligence、export、provenance、distance-intelligence、graph-analytics）未整篇精读（E-SKIP-01），涉及这些主题的论述以 reference 为准；如后续发现冲突需回补。
2. **案例项目的未完成部分**：StockInsight 的 std→final 契约只有规划（E-SI-03），文档引用时只能覆盖已验证链路，数据域 3/4/5（行情/基本面/宏观）的实操代码本使命无法从案例中取材——相关阶段示例改为「公告+新闻域已验证，其余域按同一契约延展」的写法。
3. **书稿非全书**：只收录第六章 6.1/6.2（预处理+建模），「入库/平台/实施」三环只有章引言一句话（E-BK-01 前注），篇1 讲五环联动时不越界展开后三环。
4. **LLM 相关示例的非确定性**：抽取/建模示例依赖 LLM 输出，最小链路验证用 pattern 法与确定性断言兜底，LLM 段落标注「需 API key」。

## 效度威胁（Threats to Validity）

- **版本漂移**：结论锚定 semantica 0.6.7 + docs 0.5.0；上游升级可能改变 API 行为。缓解：文档内所有版本敏感结论标注版本号（E-DC-06 策略）。
- **实测环境的代理网络与 key 状态**：StockInsight 坑清单在特定网络/key 配置下验证（E-SI-04），他人环境可能有差异。缓解：文档写明环境前置（semantica doctor）。
- **单审计者偏差**：T 清单由一个子代理核对源码得出。缓解：关键 ✗ 项（T01/T08/T18/T19）在写文档时由主代理二次复核代码位置。
- **书稿转写残留**：7 处转写痕迹（E-BK-F）若实际是更深的结构讹误，方法论引用会带偏。缓解：29 句数核对吻合 + 编号连续完整，风险低。
