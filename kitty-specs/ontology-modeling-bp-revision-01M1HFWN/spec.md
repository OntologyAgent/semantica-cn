# 本体建模最佳实践修订

**Mission**: ontology-modeling-bp-revision-01M1HFWN

**日期**: 2026-09-03
**状态**: Draft（待用户确认）

## 一、背景与目标（为什么做）

`docs/best-practices/本体建模最佳实践.md`（现有 744 行）是一份中文的本体建模工程化指南，但其中源自 `docs/best-practices/book/` 两篇书稿（本体建模书籍第六章：预处理、建模两节）的部分内容，因书稿 OCR 识别存在文字与结构错误而被带偏。同时，该文档与官方 `docs/`、`cookbook/`、`examples/` 的最新实践之间也存在比对缺口。

本使命的目标：批判性重读书稿（只在理解层面纠偏，书稿文件不动），与官方文档、cookbook、examples 交叉比对，把最佳实践修订成**可落地执行的端到端完整方案**——读者照着文档，以 `projects/StockInsight`（已跑通真实数据的股票投资知识图谱项目）为贯穿案例，从零完成业务理解、本体设计、预处理、语义抽取、建图、冲突去重、溯源到决策记录的全流程，每个步骤都有可运行的具体代码。

## 二、用户场景与验证（User Scenarios & Testing）

**主要场景（照文档走通）**：一位知识工程师拿到一批业务文档（以 StockInsight 的公告/新闻/行情等数据为样例），从零照修订后的文档操作，能依次完成本体设计、数据预处理、抽取、建图、冲突处理、溯源与决策记录，全程不需要再去翻 Semantica 源码。

**场景二（纠偏可查）**：评审者拿 `book/` 书稿原文抽查文档中引用书稿方法论的段落，验证 OCR 错误导致的概念讹误已修正，且修正有据（原意可从上下文还原，或以官方文档为准）。

**场景三（单篇独立可读）**：读者只打开文档集中的某一篇（例如建模篇），不读其他篇也能理解本篇内容并执行其中的步骤；篇与篇之间的跳转引用是「推荐延伸」而非「必需前置」。

**边界与例外**：当书稿某段因识别错误无法可靠还原原意时，文档须明确标注存疑，并给出以官方文档为准的替代论述，不得臆测书稿原意。

## 六、成功标准（Success Criteria）

1. **走得通**：知识工程师照文档集能从零完成 StockInsight 案例的端到端本体建模流程，每个步骤的代码可直接复制运行，无需翻阅源码。
2. **纠得正**：书稿纠偏有比对记录可查；抽查文档中任一书稿引用段落，与书稿上下文或官方文档无冲突。
3. **读得顺**：任选一篇可独立阅读；全文档术语统一、首现标英文；段落衔接自然，无直译腔。
4. **不超界**：改动仅落在 `docs/best-practices/` 目录内，可由仓库变更记录验证。

## 七、关键实体（Key Entities）

- **文档集**：有序编号的最佳实践文档（含总览入口），本使命的交付物。
- **纠偏记录**：书稿原文错误 → 修正后论述的对照（评审与追溯用）。
- **代码示例**：与 Semantica 实际接口一致的步骤代码，以 StockInsight 已验证调用为参照。
- **StockInsight 数据域**：公告、新闻、行情、宏观、基本面五个主题域及其 raw → std → final 三级数据流。

## 九、假设（Assumptions）

- StockInsight 的 GUIDE.md / PLAN.md 及其已验证产物（entities.json、relations.json、graph.json 等）可作为代码示例与业务事实的来源。
- `book/` 两篇书稿为本体建模书籍第六章的预处理与建模两节，OCR 错误属局部性，方法论主干可还原。
- 文档拆分的具体粒度与篇目划分在 `/spec-kitty.plan` 阶段确定；本 spec 只约束篇数上限与独立性要求。
- 本地 `.venv` 环境可用（含 LLM API key 配置），用于验证最小可跑链路。

## 十、非目标（Out of Scope）

- 不将最佳实践翻译为英文，不改动 `docs/zh/` 翻译体系。
- 不修改 Semantica 代码或新增库功能。
- 不展开图数据库运维细节（如 FalkorDB 部署调优），仅按现有验证范围提及入库/导出。
- 不修改书稿 `book/` 下的文件。
